# OpDB Foundry — автоматизация v0.1

Дата: 2026-11-08. Статус: реализация автоматической сводки предложена в PR; исследовательские чаты не являются фоновыми процессами GitHub.

## Что автоматизировано

1. **GitHub Actions** проверяют отчётные метаданные и unit tests по PR в main и после push в main. Статус CI означает только успешность имеющихся тестов, а не доказательство корректности СУБД.
2. **Ежедневная автоматическая сводка GitHub**: после принятия workflow в main GitHub Action запускается по расписанию 05:13 UTC, читает Issues R01–R10 (#7–#16), Safety/Core/Quality (#2–#4), Integration (#5), открытые PR и последние результаты CI.
3. Результат помещается отдельным комментарием за UTC-день в **[Issue #17](https://github.com/mel2003ru-code/OpDB/issues/17)** и в GitHub Actions Step Summary. При повторном запуске в те же сутки существующий комментарий обновляется, если найден.
4. **Существующий ежедневный отчёт в ChatGPT** расширен до всех 13 направлений и запланирован на **08:00 Europe/Paris**. Это отчёт, а не самостоятельное выполнение исследований или автоматическое развёртывание.
5. По 10 направлениям R01–R10 созданы GitHub Issues, чтобы результаты публиковались с проверяемыми ссылками и не терялись в отдельных чатах.

## Откуда брать реальные результаты

ChatGPT-чаты **не синхронизируются друг с другом автоматически** и не создают PR без предоставленных полномочий и запуска. GitHub-робот не может проверить скрытый прогресс отдельных чатов. Результат считается переданным в Foundry только после появления источника в GitHub (ссылка на эксперимент, коммит, PR, тесты, хеш, точная версия инструмента).

Статус **OPEN** — не отсутствие работы, статус **CLOSED** — не доказательство PASS, статус workflow **success** — не доказательство независимой корректности OpDB.

## Безопасность и расходы

- Репозиторий остаётся Private.
- Ежедневный workflow использует `GITHUB_TOKEN` с разрешениями только на чтение репозитория, PR, Actions и запись комментария в Issues.
- В этом workflow отсутствуют автослияние PR, автоматическое обновление индексов, кодогенерация, запуск производственных серверов, доступ к боевым данным и изменение приложений.
- Код непроверенного PR не исполняется в привилегированном scheduled job; запуск происходит из main.
- GitHub scheduled jobs могут запускаться с задержкой, они не гарантируют точного времени отправки.
- Private Actions могут расходовать ограниченный бюджет минут; ежедневная задача содержит один короткий запросный job.
- Отчёт Issue #17 может присылать уведомления при подписке на Issue и с подходящими настройками GitHub. Без подписки GitHub-уведомления не гарантированы.

## Не автоматизировано (осознанно)

- Автослияние изменений Core/Safety, автодеплой, выпуск релизов и изменение production.
- Обход согласования интерфейсов ADR-002/003/004 без независимой проверки Quality.
- Автоматическое выполнение задач внутри 13 отдельных ChatGPT-чатов без отдельной инфраструктуры управления агентами.

Следующий возможный этап: ограниченный CI-агент, который создаёт небольшие PR для неопасных изменений документации и тестовой инфраструктуры, с обязательным ревью при влиянии на корректность/данные.
